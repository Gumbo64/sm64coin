# Review: main since v0.2.8 (plus the risky parts of the v0.2.8 delta)

Reviewed 2026-11-25 on branch `review-cleanup` (from `origin/main` 4a0857e). Scope: `git log v0.2.8..origin/main`
(mobile layout, touch controls and PlayView, the savestate renderer `.bss` keep-live, the limit chart axis, "Closing
in on the star" with the `rrt::child::viz` changes, the highlight reel, the tree mirror and binary edge feed, the
shared `components/ui.jsx` redesign), and from v0.2.8 the web wallet (`lib/wallet/*`, passkey derivation, the
wallet engine's `proof_id`/xz), the web miner controller/board/runtime/worker and the update notices.

## How it was checked

- Read every changed file; re-derived the seqlock, mirror and controller logic by hand.
- `web`: `npm ci && npm run build`; every `src/**/*.test.mjs` (two new ones added, see below).
- Native: `cargo check --release --workspace --all-targets` and `cargo test --release -p sm64pow -p sm64coin-miner`
  from a `git archive` copy with a fresh `CARGO_HOME`: pass (only pre-existing warnings, none in `rrt/child.rs`).
  No Rust was changed, so the wasm was not rebuilt.
- `web/wallet-wasm/test/run.sh` natively (asan/ubsan): 87 vectors, 0 mismatches against the Rust `proof_id`.
- Headless Chromium (vite preview on the review build, daemon 127.0.0.1:29781), every route at 1280x900 and 360x740,
  with and without a ROM loaded, plus `/automine?vizmock=1`: no page errors; WebGL is unavailable in this sandbox
  (`--disable-gpu`), so the live game and the 3D cloud were not exercised in a browser.

No critical finding: nothing found that submits an invalid run or someone else's run, leaks keys, or makes JS rules
disagree with Rust in a way a valid block can reach.

## Checked and fine

- Board seqlock (`put`/`read`/`all`, and the new `postMail`/`mail`): single writer per region, odd/even sequence,
  copy then re-check; regions don't overlap (`boardSize` = slots + 64 B control + 256 KiB mailbox; tested).
- Step keys: Rust `"{seed}:{frame0}:{level}:{area}:{goal:?}"` and JS `parseViz` build the same string (salts are
  small integers, no float precision loss).
- Edge encoding (`child.rs` `Edges`) matches `TreeMirror.add`/`path` (u32 id, u32 parent, u16 runs, 5-byte runs, parents
  before children); messages are posted edges-before-line, so a clip's path is in the mirror when its line arrives.
- `savestate.js` keep-live range `[0xc35a00, 104488)` equals sm64-binds' generated `RENDERER` table for the visual
  build, contains the texture cache (`0xc4b210`, its hashmap still emptied after restore) and stops below
  `keyboard_buttons_down`.
- Touch input merges into the recorded pad (`applyTouch` before the perturbation), so touch runs are ordinary proofs.
- Submit path: the proof, template and timestamp all come from the round's own template `t`; messages from older
  rounds and (now) replaced workers are ignored.
- Passkey v1 derivation matches its written spec (independent Python vectors); keys and PRF never leave the browser;
  the IndexedDB record holds only wallet2's own encrypted keys/cache. No `innerHTML`/`dangerouslySetInnerHTML`
  anywhere in `web/src`; node-supplied strings are rendered as text.
- `scripts/sm64coin-node` update notice: tag parsed to digits only, 3 s timeout, background, opt-out variable.
