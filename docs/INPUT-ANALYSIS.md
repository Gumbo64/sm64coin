# Exact input analysis in the miners (no consensus change)

Source: the input analysis of sm64-binds branch `input-analysis` (docs/INPUTS.md, docs/INPUTS-actions.md): the stick
equivalence classes (51,549 classes of the processed stick, 20,129 of Mario's derived `(intendedMag, intendedYaw)`
pair, independent of the camera yaw) and a per-action model of which controller fields a frame can consume.
Nothing here touches consensus: nodes never call it, and every sealed run is replayed before it is signed.

## 1. The replay-free canonicaliser (`pow/sm64pow/src/exact.rs`, `normalise.rs`)

`sm64pow::normalise::seal_proof_exact_report(start, parent, seed, params, pads, Method::Exact, StickPick::Model)`
(feature `normalise`). Steps:

1. One replay of the run reads Mario's action at the start of every frame and which frames the perturbation poked.
2. `exact::plan`: per frame, from the per-action table (`exact_table.rs`, generated by `scripts/gen_input_model.py`
   from the analysis' `model.json`): the stick atoms the action consumes, the button levels and press edges it
   consumes. Buttons: an exact dynamic programme per bit over the whole run (fewest set bits, then fewest
   transitions) keeps every consumed level and edge and clears the rest (bits 0x40/0x80 are masked off by the game).
   Sticks: any member of the class of the consumed atoms (`exact::classes(mask)`, built in tens of ms): the
   representative, or with `StickPick::Model` the member the sealing codecs' guide model prices lowest (the stick as
   played, the previous frame's, the representative, neutral, the model's favourites).
3. Left alone: poked frames (the perturbation overrides the whole pad; never changed), the first frame, the last
   `PIN_TAIL` = 3 frames (so the controller latches in the end state match), actions not in the table, everything after a
   Start press, and cutscene-group actions also keep what the pause/dialog menu reads (raw stick, A, B, Start), because the
   model attributes dialog frames to the menu row, not to the action.
4. The check, before anything is sealed: replay the canonical run from the start; every frame must play the pad it was
   given with the same poke flag and the same perturbation view (clock and digest) as the original, and the end must have
   the same whole-memory hash and the same perturbation state and frame count. Then the sealed blob must decode to the
   run and replay valid with the original's end state (`check_sealed`, as for the replay-guided normaliser). Any doubt
   falls back to the run as played. The first version of the rules failed this check on a fixture block (A cleared during
   a dialog, which the model had attributed to the menu): the check did its job, and the dialog rule above is the fix.

Limit: the per-action model is a union over the corpus (and probes), not the per-frame trace, so it is much less precise
than the analysis' canonicaliser (which needs the instrumented game build): the camera predicates (`nonzero`,
`stickY > -16`) are in nearly every action's row, so a neutral stick is almost never allowed, and the savings are
the class-level ones (docs/INPUTS.md section 5 compares the exact rules with the replay probes).

Options: `automine --exact-normalise`, `MiningEnv::proof_exact()` (SDK), web miner `normalise_exact` (default true;
`normalise` keeps the replay-guided one and takes precedence), `rrtbench --compare-normalisers`.

## 2. Stick classes in the search (`sm64-AI-binds`, branch `input-actions`, `search/src/padspace.rs`)

`OBRRT_STICK_CLASSES=off|processed|intended` (default `off`). The pink-noise sampler, the random segments and the GA's
stick mutations (Gaussian nudge of key frames, turn) write class representatives. A nudge that stays in the class of the
stick it started from (a full-tilt stick is clamped: most nudges do) is repeated doubled, up to 5 times, until it leaves
the class, so fewer rollouts replay an identical input. `intended` classes are those of (nonzero, intendedMag,
intendedYaw, stickY > -16): exact for the many actions that read only Mario's derived pair, a coarser action space for the
38 that read the processed stick (pole, swimming, flying, ...); `processed` is exact for every gameplay reader.
Skipping button bits the current action cannot read was not done: the genome is a pad list and the action is only known
when it is played.

Paired runs (`rrtbench`, 2 threads each, seeds 1-4, same seeds both arms; segment p = block 1 from power-on, f = block 2
from the end state of fixtures/power_on_star.json; simulated frames until the first valid run, and its length):

| segment | arm | simulated frames (M), seeds 1-4 | mean | run length (frames) | mean |
|---|---|---|---:|---|---:|
| p | off | 46.6 71.3 76.3 33.7 | 57.0 | 3945 5743 5578 4908 | 5044 |
| p | intended | 60.8 54.0 58.0 98.4 | 67.8 | 4895 3882 5672 6224 | 5168 |
| f | off | 31.6 23.5 49.1 40.3 | 36.1 | 3006 2372 4390 3162 | 3232 |
| f | intended | 24.5 27.7 36.8 26.8 | 28.9 | 2846 2458 4287 3596 | 3297 |
| f | processed | 21.0 29.4 45.6 33.0 | 32.3 | 2424 2885 3558 3176 | 3011 |

`intended` is not better (worse on p, better on f, nothing outside the noise of 2x between seeds; its plain proofs are
~10-15 % larger since representative sticks are less regular), so the default stays `off`. `processed` (exact for gameplay)
was only run on f: within the noise, not shown to be better either. Nothing is enabled by default.

Canonicaliser on the v0.2 fixture blocks 2-16 (50,412 frames, 15 blocks; block 1, power-on, is left alone: 100.7 %), sealed sizes:
original 19,894 B; replay-guided normaliser (conservative+aggressive) 15,606 B (78.4 %) at 6-26 s per block;
exact canonicaliser 18,724 B (94.1 %) at 0.08-0.27 s for the canonicaliser, 0.5-1.5 s for the whole seal; exact followed by the
replay-guided pass 15,759 B (79.2 %). Fresh runs (rrtbench --compare-normalisers, 3204 and 3630 frames): plain 1238 / 1449 B,
exact 1167 / 1325 B (94.3 / 91.4 %, 0.5 s), replay-guided 1007 / 1085 B (81.3 / 74.9 %, 12 s).
